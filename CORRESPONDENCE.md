# Reach out to the authors

Users may contact the authors for several types of requests:
1. Code repository issues.
2. Requests for controlled-access materials.
3. Follow-up collaboration.

To reduce communication overhead and help users identify the most appropriate contact route, 
we provide the following recommendations for different types of requests.

## Code repository issues

If users identify potential bugs in the code repository or encounter problems when executing the provided pipelines, 
they are encouraged to first raise an issue directly in the code repository. 
This helps keep the discussion traceable and 
allows other users to refer to the reported issue and any subsequent clarification.

If no response is received within two weeks, users may contact the first author, 
[Haoling Zhang](mailto:zhanghaoling@genomics.cn), 
and copy the corresponding author, 
[Dr. Zhi Ping](mailto:pingzhi@cuhk.edu.cn).

For efficient diagnosis, we recommend that the report include the following information where applicable:
1. The email subject, for example: "Questions about running the SPIDER-WEB code repository".
2. The relevant script or pipeline step.
3. The command-line instruction, configuration, or parameter settings used to run the script.
4. The operating system, Python version, and relevant package versions.
5. The input files or file paths involved in the failed or unexpected execution.
6. The complete error message, traceback, or relevant running log.
7. A brief description of the expected behaviour and the observed behaviour.

Please note that an unexpected behaviour does not necessarily indicate a software bug. 
It may arise from an intended feature, an expected boundary condition,
differences in hardware or system configuration, or other platform-dependent factors. 
Before reaching out the authors, users are encouraged to repeat the same execution steps 
under the same configuration to determine whether the behaviour is reproducible.

## Requests for controlled-access materials

In most cases, controlled-access materials refer to the C++ executable program `accelerator` 
associated with the [`sbw`](https://github.com/BGI-SynBio/SPIDER-WEB/tree/main/sbw) directory. 
This executable is not distributed as part of the public source-code release.

For intended uses such as third-party evaluation, independent analysis, customised experiments, or benchmarking, 
users are encouraged to contact the first authors, 
[Haoling Zhang](mailto:zhanghaoling@genomics.cn) and [Xiaoyi Lin](mailto:xiaoyi.lin@stu.hit.edu.cn), 
and copy the corresponding authors, 
[Prof. Bo Liu](mailto:bo.liu@hit.edu.cn) and [Dr. Yue Shen](mailto:shenyue@genomics.cn).

To help the authors assess the request, the email should include the following information where applicable:
1. The email subject, for example: "Request for controlled-access SPIDER-WEB material: accelerator".
2. The user's name, affiliation, position, and institutional email address.
3. The requested controlled-access material, typically accelerator. 
4. The intended use of the requested material, such as third-party evaluation or systematic benchmarking.
5. A brief description of the planned analysis or experiment.
6. Whether the requested material will be used only internally or shared with additional collaborators.
7. The expected timeline of use, for example: three months.

When controlled-access materials are provided to specific users, 
the authors may set the validity period of the provided executable 
according to the expected timeline of use stated in the request. 
Users may submit a new request after the validity period has expired if continued access is needed. 
Unauthorised reverse engineering, decompilation, disassembly, redistribution, circumvention of access controls, 
or other unlawful use of the provided materials is strictly prohibited. 
The authors reserve all rights to protect their lawful interests through all available means.

At this stage, experiments that require coordination with specific hardware devices, 
such as the demonstration experiments reported in Fig. 6 of the publication, 
cannot be directly reproduced by third parties using this code repository alone. 
For requests concerning the replicability of these hardware-coupled experiments, 
please contact [Dr. Yue Shen](mailto:shenyue@genomics.cn).

Please note that access to controlled-access materials is not guaranteed. 
Requests will be considered based on the stated purpose, feasibility, data-use constraints, 
software-distribution constraints, and applicable institutional or legal requirements.

## Follow-up collaboration

Users interested in follow-up collaboration are encouraged to contact the corresponding authors, 
[Dr. Yue Shen](mailto:shenyue@genomics.cn), 
[Prof. Bo Liu](mailto:bo.liu@hit.edu.cn), 
[Prof. Yiwei Zhang](mailto:ywzhang@sdu.edu.cn), and 
[Dr. Zhi Ping](mailto:pingzhi@cuhk.edu.cn).

Potential collaboration topics may include, but are not limited to, 
mathematical analysis, theoretical modelling, methodological extensions, independent validation, 
benchmarking, adaptation, or integration with other efforts in the field.
Although we cannot commit to supporting unrelated studies or directly competitive follow-up studies, 
we remain strongly committed to facilitating constructive community development 
and welcome collaboration proposals that are scientifically relevant, feasible, and aligned with 
the broader advancement of DNA-based data storage.

To help the authors assess the potential collaboration, 
the email should include the following information where applicable:
1. The email subject, for example: "Follow-up collaboration based on SPIDER-WEB".
2. The user's name, affiliation, position, and institutional email address.
3. A brief description of the proposed collaboration topic.
4. The specific part of SPIDER-WEB that the proposed collaboration relates to.
5. The expected contribution from the user or the user's team.
6. The expected contribution requested from the SPIDER-WEB authors.
7. Any relevant preliminary results, datasets, experimental systems, or computational resources.
8. The expected timeline and intended outcome of the collaboration.

Please note that follow-up collaboration requests will be considered based on scientific relevance, feasibility, 
available time and resources, and alignment with the authors' ongoing research priorities.
